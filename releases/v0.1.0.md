# steward v0.1.0

the project's own units and checklist. Landing stays manual unless the project turns it on.

## Known issues

- **A landing starts no `push` workflows.** The runway merges with `github.token`, whose events start no new workflow runs, so CI or a deploy on `push` to `main` does not run after `steward land`. To run them, trigger on `workflow_run` of `Land approved PRs`, with the guard `github.event.workflow_run.head_sha != github.sha`. `workflow_run` runs only on the default branch, so a release branch gets no run after a landing. ST-75.
- **A landing does not close a linked issue,** for the same reason. Close it by hand. ST-76.
- **An existing checklist is not parsed at installation.** A `## ` section with no numbered item gets every review refused as `rules-unreadable`, including the pull request that repairs it. Check your checklist before merging `init`'s pull request. Afterwards, the way through is to remove `review/agent` from the required checks and merge the repair by hand. ST-78.
- **`init`'s files can fail a Prettier check.** Format them in the installation pull request. ST-74.
- **`init` overwrites nothing,** so a project with its own files of the same names keeps them, and has no thin workflows until it removes them. When every file is there, `init` says the installation is complete.
- **Findings can arrive one review at a time.** Two reviews of one head can block on different findings, and three blocks raise `review-blocked`.
